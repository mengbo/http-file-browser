# ADR-0004：默认只读，开放远程访问与写入均须显式开启

- 状态：accepted
- 日期：2026-10-04
- 关联：Change 13 `add-remote-access`；长期约束见 [roadmap 愿景](../roadmap.md) 与 ADR-0001

## Context

服务最初只监听 `127.0.0.1`、且整个 HTTP 表面只读，安全姿态是「最小暴露」，但一直只是口头约定，没有一条长期决策把它固定下来。Phase 4 引入远程访问：新增 `--listen` 允许监听非回环地址，一旦监听 `0.0.0.0`，同网段任何主机都能读取所浏览目录的内容。随后 Phase 3 的文件编辑还会引入写入，那是比只读更重的暴露面。

如果每个新能力都默认开启，安全边界会随功能增长不断后退，且每次都要重新争论。需要一条一次性的决策，规定「扩大暴露面的能力如何进入系统」。

## Decision

系统默认只读，且默认只监听回环地址。任何扩大暴露面的能力都必须由用户**显式指定**才启用：

- 开放远程访问：必须显式指定非回环监听地址（`--listen`），默认不监听。
- 开放写入：必须显式开启写模式，默认拒绝写请求。

未显式开启时系统不提供这些能力。启用远程访问时系统同时启用访问凭证认证，**不存在「远程可访问但无需认证」的中间状态**——暴露到网络与要求凭证是同一个决定，必须一次落地。

## Alternatives

- **默认非回环、按来源 IP 判定是否要认证**：对局域网更顺手，但引入逐请求 IP 解析与「反向代理后 `RemoteAddr` 不可信」的问题，规则不再是「暴露到网络 = 要凭证」一句话。放弃。
- **先开放远程、后补认证**：会在两次发布之间留下「远程可访问且无需认证」的不安全窗口。放弃，这也是原 13（监听地址）与 14（Token 认证）合并为一个 Change 的直接理由。
- **默认可写、写操作再逐项收紧**：与「默认只读」相反，任何一次遗漏都是写权限失守，代价不对称。放弃。

## Consequences

- 默认启动的用户行为零变化：仍是 `127.0.0.1:8080`、无凭证、只读；安全边界默认收紧。
- 后续每个扩大暴露面的 Change（文件编辑、Host 校验、写冲突处理等）都要回答两个问题：能力默认是否关闭、显式开启的入口是什么；验收要覆盖「未开启时确实不可用」。
- 代价：局域网使用需要用户显式传 `--listen` 并携带凭证，比「启动即可远程」多一步。接受，换取默认安全。
- 本 ADR 是 Phase 4 安全姿态的落点；被推翻时标 superseded 并另写新条，不修改历史。
