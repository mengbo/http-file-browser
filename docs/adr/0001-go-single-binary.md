# ADR-0001：技术栈选 Go，单二进制交付

- 状态：accepted
- 日期：2026-10-03
- 关联：Change 01 `bootstrap-http-server`；ADR-0002；docs/roadmap.md 愿景

## Context

项目愿景是零配置 HTTP 文件浏览器：命令行指定目录即启动服务。教材 §40 明确技术栈不应在起步时拍脑袋定，而应按约束（零配置、启动快、资源占用低、文件系统访问、静态资源、远程访问、未来编辑）比较后决策。同时本项目是 OpenSpec SDD 学习实验场，首要目标是走通 Spec 驱动开发全流程，开发摩擦必须小，学习注意力不能被语言与工具链本身吃掉。

2026-10-03 的架构探索中确认两点：单二进制（一个可执行文件、不依赖语言 runtime）是硬约束；开发难度要求适中。

## Decision

技术栈选 Go。程序以单二进制交付，HTTP 服务器与前端静态资源一并内嵌（`go:embed`），分发不依赖任何语言 runtime。

## Alternatives

- Rust：同样满足单二进制，但学习曲线陡、开发速度慢，对以 SDD 学习为首要目标的项目不划算。
- Node.js：生态成熟、迭代快，但分发依赖 runtime 或引入复杂打包，破坏单二进制约束。
- Python：同样依赖 runtime，单文件分发能力更弱。

## Consequences

- 前端静态资源随 `go:embed` 内嵌；本项目前端保持零构建（见 ADR-0002），无独立前端构建流水线。
- 后端从标准库 `net/http` 起步，不急于引入 Web 框架；依赖数量保持克制。
- 渲染类需求（语法高亮、Markdown）放浏览器端，以 vendored 静态文件引入，不新增后端依赖。
- 交叉编译容易，后续远程访问阶段（Change 13+）分发成本低。
- 代价：Go 的前端生态弱于 Node，前端能力靠 vendored 库与手写 JS 补足。
